## LeCrypto (crypto, 250)
Source: [lecrypto](https://github.com/p4-team/ctf/tree/master/2016-11-11-defcamp-2016-finals/lecrypto) (bilingual EN/PL)

**Setup.** Python 2 code that encrypts a message with RC4, plus its output: a salt `s`, an encrypted random 16-character value `v`, an encrypted MD5 of `v`, and the encrypted message.

**Where it breaks.** RC4 itself is implemented correctly. The weakness is the key derivation. The RC4 key is `md5(h1[:8] + "00"*4)`, where `h1` is itself an MD5. The input to that last MD5
therefore contains only **eight hex characters = 4 bytes (32 bits) of unknown**, followed by fixed zeros. MD5s everywhere make the chain irreversible, but the search space is only 2³².

**Attack.**
1. Enumerate all 2³² four-byte values, build the resulting key for each, and decrypt the encrypted `v`.
2. `v` is known to consist of 16 characters in the printable range 32–125, so discard any key whose decryption of `v` falls outside that range.
3. Run it in parallel (split on the first byte). A set of candidate keys survives, since the filter is only a plausibility test.
4. Decrypt the message with each candidate and read the flag from the one that gives text.

**Takeaway.** A long-looking hash chain is only as strong as its smallest unknown. A known plaintext property (printable range) is enough to confirm a key without knowing the plaintext.
